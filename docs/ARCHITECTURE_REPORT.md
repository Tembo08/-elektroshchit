## 1. Что это за приложение

«Электрощит» — калькулятор квартирного и домового электрощита. Отвечает на
вопрос «что купить и как собрать», а не «сколько розеток в комнате».

Пользователь вводит объект, комнаты и приборы; приложение считает линии,
автоматы, УЗО, сечения кабеля, падение напряжения, распределение по фазам,
выдаёт спецификацию, PDF-отчёт и схемутический план помещения.

Главный принцип: **расчёт — черновик**. Приложение честно предупреждает, что
итог должен проверить квалифицированный электрик, и подсвечивает ошибки
вместо того, чтобы их прятать.

**Ключевое решение:** расчётное ядро — отдельный пакет без зависимости от
Flutter. Его можно тестировать обычным `dart test`, переиспользовать в
консоли или сервере, и оно не тянет UI.

### 2.2. Поток данных

```

        ▼
```

### 2.3. Управление состоянием

Riverpod 2.6.1. Главные провайдеры:

| Провайдер | Файл | Назначение |
|---|---|---|
| `normsProvider` | `core/providers.dart` | асинхронная загрузка YAML-норм |
| `projectDraftProvider` | `core/project_draft.dart` | черновик проекта (Notifier) |
| `projectStoreProvider` | `data/project_store.dart` | сохранение/загрузка |
| `planEditorProvider` | `presentation/plan/plan_providers.dart` | режим, выделение, слои |
| `planGroupLabelsProvider` | там же | группы по комнатам |

Черновик (`ProjectDraft`) — immutable-класс с `copyWith`. Внутри —
`FloorPlan? plan`, который сериализуется вместе с проектом.

### 2.4. Хранение

`SharedPreferences` + JSON. Проект хранит: название, тип объекта, фазы,
площадь, потолки, заземление, комнаты (с приборами), **план** (стены,
проёмы, устройства, щит), разрешённую мощность.

Формат плана — `plan_models.dart`, метод `toJson/fromJson`. Есть
`planVersion` в перспективе (см. ТЗ), сейчас не введён.

### 3.2. Формулы

| Величина | Однофазная | Трёхфазная |
|---|---|---|
| Ток | `I = P·1000 / 230` | `I = P·1000 / (3·230)` |
| Падение напряжения | `ΔU = 2·I·L·ρ / S` | `ΔU = √3·I·L·ρ / S` |
| Процент | `ΔU% = ΔU / 230 · 100` | `ΔU% = ΔU / 400 · 100` |

ρ = 0.0225 Ом·мм²/м (медь). Норма падения — 5 %.

Коэффициенты спроса (`grouping_rules.yaml`):

- розетки — 0.7
- освещение — 1.0
- мощные приборы — 1.0

### 3.3. Нормы

Шесть YAML-файлов, продублированы в двух местах:

- `assets/norms/ru_2026/` — для приложения (через `rootBundle`)
- `packages/electrical_core/lib/src/norms/ru_2026/` — для тестов

| Файл | Что внутри |
|---|---|
| `breakers.yaml` | ряд номиналов автоматов |
| `cable_sections.yaml` | сечения, допустимые токи |
| `rcd.yaml` | УЗО: номиналы, ток утечки |
| `grouping_rules.yaml` | коэффициенты спроса, лимиты точек на линию |
| `room_defaults.yaml` | типовые мощности по типам комнат |
| `stop_scenarios.yaml` | тексты проверок и уровни важности |

**Дублирование — риск:** файлы должны совпадать. Проверять при правках.

### 3.4. Публичный API

```dart
class CircuitCalculator {
  final NormsCatalog norms;
  const CircuitCalculator(this.norms);

  CalculationResult calculate(
    Project project, {
    int? inputBreakerAmps,
    int lightingLines = 2,
    int socketLines = 2,
  });
}

class CalculationResult {
  final List<CircuitGroup> groups;        // линии
  final PanelResult panel;                // спецификация щита
  final List<String> warnings;
  final CircuitGroup? inputGroup;         // ввод
  final PhaseBalance? phaseBalance;       // баланс фаз (3ф)
  final List<CalcIssue> issues;           // проверки с уровнями
}
```

### 3.5. Логика расчёта (схема)

1. **Валидация потребителей** — нулевые мощности, число фаз.
2. **Разбиение на линии** — `_pack`: не больше лимита точек и мощности на
   линию, по комнатам (монтажник не тянет провода из разных комнат).
3. **Розеточные линии** — ток → автомат (не больше 16 А), ΔU по длине.
4. **Освещение** — отдельные линии, минимум по норме.
5. **Мощные приборы** — каждый на своей линии.
6. **УЗО** — группировка по требованиям (санузел — 30 мА).
7. **Баланс фаз** — распределение групп по L1/L2/L3.
8. **Проверки** — `stop_scenarios.yaml`, уровни: ошибка/предупреждение/совет.
9. **Спецификация** — модули, корпус, автоматы, УЗО, кабель.

### 4.2. Модель данных

```dart
class FloorPlan {
  final double widthM, heightM;          // лист в метрах
  final List<PlanRoom> rooms;            // комнаты (прямоугольники)
  final List<PlanDevice> devices;        // точки
  final PlanPanel panel;                 // щит
  final List<PlanWall> walls;            // стены с толщиной
  final List<PlanOpening> openings;      // двери и окна
  final double? corridorY;               // ось коридора для трасс
}

class PlanDevice {
  final String id, roomId;
  final PlanPointType type;   // socket / light / switchPoint / powerful
  final double x, y;          // метры, от левого верхнего угла листа
}
```

**Все координаты — в метрах.** Это требование ТЗ и залог того, что длины
трасс сразу получаются в метрах.

### 4.3. Два генератора

| Генератор | Что даёт | Когда использовать |
|---|---|---|
| `PlanAuto` (эскиз) | сетка комнат, точки по расчёту, щит | быстро посмотреть, где что стоит |
| `PlanLayout` + `PlanLayoutDevices` | стены, проёмы, коридор; точки поверх | ближе к реальной планировке |

Переключение — в меню плана, план пересобирается сразу.

### 4.4. Отрисовка

`PlanCanvas` (CustomPainter) рисует слоями:

1. лист (белый) → 2. сетка (в редакторе) → 3. комнаты → 4. трассы
(если включены) → 5. стены → 6. проёмы → 7. устройства (УГО по ГОСТ 21.614)
→ 8. подписи комнат → 9. щит → 10. номера групп → 11. линейка масштаба.

УГО:

- **розетка** — полукруг куполом вверх, два контакта вверх, защитный контакт
  вниз;
- **светильник** — круг с крестом;
- **выключатель** — отрезок с наклонной насечкой;
- **мощная точка** — двойной круг.

Цвета групп: голубой, розовый, красный, синий, зелёный, оранжевый.

### 4.5. Редактирование

| Действие | Как |
|---|---|
| Перенос комнаты | тянуть середину |
| Изменение размера | тянуть грань (мин. 1.2 м, шаг сетки 0.25 м) |
| Перенос точки | тянуть символ |
| Добавить точку | тап по комнате в режиме «Точки» |
| Удалить точку | выбрать → «Удалить» |
| Перенос щита | режим «Щит» |
| Пересоздать / сбросить | меню в AppBar |

### 4.6. Связь с расчётом

`PlanSeed.applyToDraft(draft, plan)` переносит площади и `cableLengthM` из
плана в комнаты черновика. Дальше расчёт ΔU идёт по реальным длинам.
Вызывается из меню: «Обновить длины из плана».

## 10. Известные ограничения и техдолг

1. **Нормы продублированы** в `assets/` и `packages/` — правка требует
   синхронного изменения обоих файлов.
2. **Эмулятор Android не настроен**: системный образ не скачивается
   (сеть), проверка вёрстки — через golden-скриншоты.
3. **Ручной чертёж стен** (этап 5 ТЗ) не начат: сейчас комнаты —
   прямоугольники, стены генерируются.
4. **`lib/plan/svg_import.dart`** — импорт из Corel/Inkscape написан, но
   не подключён к UI (лежит для будущего).
5. **`archive/plan_ui/`** и `lib/presentation/home/archive/` — старые
   экраны, не используются, можно удалить.
6. **Трассы** считаются «по манхэттену» с запасом 15 %, без обхода стен.
